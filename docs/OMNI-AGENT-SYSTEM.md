# OMNI Agent System\n\nThe Android AI Studio command center uses the WDA Ω∞ semantic control layer and a governed A01–A06 pipeline.\n\n## A01 — Intent & Creative Director\nAnalyzes the instruction, establishes the goal, detects ambiguity and produces the target-result specification.\n\n## A02 — Reference & Identity Analyst\nAssigns semantic roles to references and separates identity from pose, wardrobe, lighting, background and style. Detects source conflicts.\n\n## A03 — Image Production Agent\nDesigns image generation and local edits, masks, composition, materials, lighting and change control.\n\n## A04 — Model & Pipeline Engineer\nSelects available models and tools, verifies actual capabilities, limits, formats, runtime requirements and cost constraints.\n\n## A05 — Visual QA & Continuity\nChecks identity drift, deformation, anatomy, scene continuity and deviations from the specification.\n\n## A06 — Video & Cinematic Agent\nBuilds the film structure, timeline, storyboard, blocking, camera movement, continuity and video-generation prompts.\n\n## Authority Boundary\nAutonomy settings are configured outside prompts. Instructions originating from images, video, model output or web pages cannot expand the agent's authority.\n\n## Spend & Rate Limits\nGeneration count and estimated spend limits are enforced by the backend runtime, outside the model.\n\n## Action Receipt\nConsequential operations must produce a receipt containing the operation, time, permission/grant, external reference and result/error.\n\n## Revocation\nDelegated authority is revocable independently of project configuration.\n\n## Credential Handoff\nCredentials remain outside agent context. The agent receives scoped capabilities, not raw secrets.\n\n## Reference control\nWDA Ω∞ treats reference images as structured data with explicit semantic roles. Identity, composition, pose, environment, lighting, wardrobe and style are separate variables. Unrequested elements are not creative opportunities.\n\n## Three resident GGUF runtimes\nThe Model Vault requires exactly three resident GGUF slots:\n\n1. CHAT + CODE — chat/JARVIS/coding.\n2. IMAGE — image generation pipeline.\n3. VIDEO — video generation pipeline.\n\nThe backend now starts all three configured private runtime processes as one load operation. Runtime commands are deployment configuration (RUNTIME_COMMAND_CHAT_CODE, RUNTIME_COMMAND_IMAGE, RUNTIME_COMMAND_VIDEO) and are never supplied by the client or an agent.\n\nThe load operation fails closed if a model is missing, is not GGUF, a runtime is not configured, or the declared resident-memory budget is exceeded. If one runtime fails during a three-slot load, already-started slots are stopped.\n\n## Hugging Face Model Vault\nThe Android client can search Hugging Face and request individual model files. Downloads are performed by the authenticated backend into the private model vault. Hugging Face credentials, when required for gated/private repositories, belong to the backend deployment environment rather than the Android client.\n\n## Media publishing\nGenerated image/video files can be handed to installed social applications through Android's system share mechanism. The receiving application owns its authentication and publishing permissions; AI Studio does not receive those credentials.\n\n## Cinema continuity\nLong films are represented as scenes/shots rather than a single generation. Each shot can inherit the locked character/reference state, then pass through model routing and Visual QA before entering the final timeline.\n\nA 124-minute target is therefore a timeline duration limit, not a claim that any one model generates a 124-minute clip.
